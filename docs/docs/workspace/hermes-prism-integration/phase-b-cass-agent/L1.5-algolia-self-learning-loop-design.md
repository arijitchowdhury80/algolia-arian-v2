# Phase B — Algolia Self-Learning Loop (ASL) — Design

**Date:** 2026-06-29
**Status:** DESIGN — decisions locked, ready to build (combined with L1, shared plugin path)
**Relation:** Dynamic evolution of Gap 1 (static knowledge) + brain of Gap 3/L2 (tool-arms).
Connects to in-progress W-H "exploit Hermes self-learning loop". Reuses `ai-judge` skill.

---

## The idea (user, 2026-06-29)

Cass learns Algolia by conversing. When Algolia comes up she: answers from her KB, asks the
clarifying / question-behind-the-question, expands into N sub-queries, runs Gemini + Google-Search
grounding, records the SOURCED answers into a growing Algolia KB, and answers from that KB next
time. A self-improvement loop, packaged as a skill, used immediately, with a cron that keeps
learning + testing itself for improvement.

## The hard constraint (why two arms)

Cass has zero tool-calling today (Gap 3) → she cannot search live mid-chat until **L2**. So the loop
runs **gap-driven** now and goes **real-time** at L2. Same loop, two execution modes:

```
CONVERSATION (L1 today)             CRON LEARNER (today)              INJECTION (today)
Algolia Q the KB can't fully    ─►  read gap log; for each gap   ─►  grown KB (seed+learned)
answer → answer what she can,       + seed curriculum item:           injected every turn →
LOG the gap (passive, no tool).     Gemini+Google-Search grounding    Cass answers from KB.
                                    → quality gate → record.
L2 later: same loop, but Cass calls the search tool LIVE and records instantly (Hermes tool).
```

## Locked decisions

1. **Scope:** gap-driven now; live mid-chat search folds into L2 as a Hermes tool. (Nothing wasted.)
2. **Quality gate on entry:** an answer enters the KB only if it has ≥1 real source URL AND passes
   the `ai-judge` grounding score. Else rejected + gap re-logged. (This = "test for improvement".)
3. **Learning source:** logged real conversation gaps (primary) + seed Algolia curriculum (bootstrap).

## ARCHITECTURE REVISION (2026-06-29) — DB, not MD files (user directive + recon)

User pushback: knowledge belongs in a DATABASE (parallel to memory), not static MD. Recon CONFIRMED
the right foundation already exists:
- `prism` Postgres (prism-platform-postgres-1, PG16) already has an Algolia knowledge schema, ALL EMPTY:
  `algolia_case_studies, algolia_proofpoints, algolia_quotes, algolia_customers, algolia_advocates,
  vertical_benchmarks` (defined in `/opt/prism-platform/prism_platform/db/models.py`).
- pgvector NOT installed → semantic search deferred; Postgres built-in full-text search (tsvector)
  CONFIRMED working → keyword retrieval v1, embeddings/pgvector later.
- hermes-prism container has `httpx` (plugin already uses it) but NO psycopg; asyncpg present but plugin
  is sync. hermes-prism is network_mode:host → reaches `http://127.0.0.1:8000` (prism_platform) —
  PROVEN from inside the container.
- prism_platform healthy at 127.0.0.1:8000; routers in `api/routers/`; alembic at head.

**Decision: plugin talks to prism_platform over HTTP (httpx, already present); prism_platform owns the DB.**
This avoids a DB driver in the Hermes container AND makes `/knowledge/retrieve` the first L2 tool.

```
PLUGIN (httpx)                          PRISM_PLATFORM (owns DB)              POSTGRES (prism)
pre_llm_call: POST /knowledge/retrieve  → FTS top-k over case_studies/     → algolia_knowledge (NEW)
  → inject only relevant rows             proofpoints/quotes/knowledge        algolia_case_studies...
  POST /knowledge/gaps                   → write gap                        → algolia_gaps (NEW)
CRON learner: Gemini+search → ai-judge  → POST /knowledge (gated write)     → algolia_knowledge
```

### 1. Knowledge store = Postgres (REPLACES the two-MD-file plan)
- REUSE existing empty tables for structured facts (case studies, proof points, quotes, customers, benchmarks).
- ADD `algolia_knowledge` (general Q&A: id, topic, question, question_hash UNIQUE, answer, sources jsonb,
  confidence, judge_score, origin ['seed'|'learned'], learned_at, updated_at, fts tsvector GENERATED).
- ADD `algolia_gaps` (id, ts, question, question_hash, topic, conversation_id, status ['open'|'resolved'],
  why ['kb_miss'|'low_confidence']).
- Retrieval v1 = Postgres FTS (`to_tsvector @@ plainto_tsquery`) ranked by `ts_rank`, top-k. pgvector later.
- The curated seed pack (`KNOWLEDGE-algolia-full.md`) is now SEED DATA: a one-time loader parses it into
  algolia_case_studies / algolia_proofpoints / algolia_quotes / algolia_knowledge rows (origin='seed').
- New prism_platform router `api/routers/knowledge.py`:
  - `POST /api/v1/knowledge/retrieve` {query, k} → top-k structured + Q&A rows (for plugin injection + L2 tool).
  - `POST /api/v1/knowledge/gaps` {question, topic, conversation_id, why} → insert gap.
  - `POST /api/v1/knowledge` {topic, question, answer, sources, confidence, judge_score, origin} → gated write (learner).

### 2. Gap log (works at L1 — passive)
- `/opt/data/algolia-kb/gaps.jsonl` on VPS. Each line: {ts, question, topic, conversation_id,
  why_gap: "kb_miss"|"low_confidence", asked_by}.
- Detection: a lightweight pre/post hook in the plugin flags turns that (a) are Algolia-topic AND
  (b) the KB likely didn't cover (heuristic: topic keyword present, no strong KB hit). No tool-calling
  needed — just append a line. Dedup by normalized question hash.

### 3. Cron learner (`learn-algolia.py`) — buildable now
- Queue = unresolved gaps (gaps.jsonl) ++ seed curriculum (`seed-curriculum.md` — products,
  competitors, verticals, objections, integrations).
- Per item: optionally expand into sub-queries (question-behind-the-question) → call Gemini
  `generateContent` with `tools:[{google_search:{}}]` (grounded) → collect answer + grounding source
  URLs.
- **Quality gate:** require ≥1 grounding source URL; run `ai-judge` grounding score on
  (answer, sources); pass threshold → record; fail → reject + mark gap unresolved (retry next run).
- Record to `knowledge.learned.md` as a structured entry: `### <topic> — <question>` + answer +
  `[SOURCE: url]` labels + `learned: <date>`. Dedup by question hash; update if newer/better.
- Then redeploy/refresh the KB to the live plugin path (scp or shared volume).

### 4. Self-eval (the "test your skill for improvement" cron)
- Weekly: metrics = KB entry count, coverage growth, ai-judge grounding pass-rate, gap-resolution
  rate, regression check (re-judge a sample of existing entries; flag any that now fail).
- Writes `kb-eval-<date>.md`. If pass-rate drops below threshold → alert (don't silently rot).

### 5. Skill packaging
- Claude Code skill `algolia-self-learn` in arijit-skills (the cron arm runs via claude-cli/python).
- SKILL.md documents the conversational playbook (detect → probe → question-behind-question → expand
  → search → gate → record) so the SAME procedure drives the live L2 Hermes tool later.

### 6. Cron
- `learn-algolia.py` on a schedule (e.g. every 6h or nightly) on the VPS.
- `eval-algolia-kb.py` weekly.
- Use Hermes-native cron OR system cron/systemd-timer on the VPS (decide at build; Hermes cron per
  MEMORY "Temporal dropped — Hermes-native kanban/cron is the orchestrator").

## Build order (combined L1 + ASL, one plugin pass)

1. Plugin: load+inject seed KB (L1 Gap 1) → add learned KB load+inject → two-source judge (L1) →
   gap-logging hook (ASL #2). Binding fixes (L1 Gap 2: accent/token/session-key).
2. `learn-algolia.py` learner with quality gate (ASL #3) + tests on pure logic.
3. `seed-curriculum.md`.
4. Deploy to VPS, live-test (T1–T5 from L1 design + new: gap logged → cron learns → KB grows → Cass
   answers from learned entry).
5. Cron wiring + first self-eval.

## TDD targets (pure functions, test first)
- binding: `_norm()` accent/stopword; token-alias match ("homedepot"→homedepot-mexico).
- gap detect: Algolia-topic + kb-miss heuristic; question-hash dedup.
- KB compile: seed+learned merge, size cap.
- quality gate: reject no-source; reject ai-judge fail; accept sourced+passed.

## Risks
- KB rot if gate too loose → mitigated by gate-on-entry + weekly regression re-judge.
- Gemini free-tier quota under cron load → use paid key (per memory, VPS key is standard tier); throttle.
- Learned KB bloat → size cap now, retrieval later.
- Marketing-fluff answers from Google → ai-judge grounding + source-required gate filters.
